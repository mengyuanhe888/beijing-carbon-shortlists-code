# Study inputs

The files below are supplied separately from this code distribution. We preserve the original field names so that the analysis programs can read the study inputs without renaming columns. No panel rows, fitted coefficients, or sample identifiers are included here.

## Files required by each calculation

- `模型数据/panel.csv`: the processed 2,401-row analysis panel. Required by all analysis commands.
- `参数配置/method.json`: the study configuration, including the retained coefficients, standardization parameters, optimization starts, and holdout definitions. Required by all analysis commands, including a new fit.
- `参数配置/bootstrap_draws.json`: the recorded 1,000 samples. Required for bootstrap refitting; these are not generated by the code-only file check.
- `比较输入/edgar.csv`, `odiac.csv`, and `sectors.csv`: external-product aggregates and sector totals for comparisons and electricity-and-heat scenarios.
- `保存结果/bootstrap_frequencies_2022.csv`: saved selection frequencies used by `shortlist`.
- `thermal_shortlists_2022.csv`: scenario ranks, either supplied or generated by `compare`, used to classify core candidates.

A `parameters.json` from `predict` or `fit` contains an eight-element `beta` vector and a `scaler` object with `means`, `stds`, `scope`, and `ddof`. The coefficient order is `log_ntl`, `log_poi_density`, `log_road_density`, `log_building_density`, `green_ratio`, `industrial_ratio`, `commercial_ratio`, and `residential_ratio`. Standardization uses population standard deviations for the seven non-light variables; log nighttime light is not standardized.

The code uses internal columns `w_m0`, `w_m1`, `w_m2`, `w_m3`, and `w_m4` for paper models M1, M2, M3, M4, and M4′, respectively.

## Data definitions

We match records by year and subdistrict identifier. The code reads numerical CSV files with `pandas.read_csv(..., float_precision="round_trip")` to preserve the stored precision.

| Panel field | Definition and unit |
|---|---|
| `year`, `street_id`, `street_name` | Year, subdistrict identifier, and name; `(year, street_id)` is unique |
| `district_code`, `district_name` | Study district code (1–16) and name; the code is an index used in the analysis, not an official administrative code |
| `area_km2` | Subdistrict area calculated in EPSG:3857, km² |
| `ntl_sum`, `w_ntl_m0` | EOG NPP-VIIRS monthly radiance summed from August of the label year through April of the next year, and its citywide share |
| `city_total` | CEADs citywide emissions, 10,000 tonnes CO₂; repeated across subdistricts within each year |
| `energy_consumption_10k_tce`, `electricity_10k_kwh` | District energy consumption (10,000 tonnes of standard coal equivalent) and electricity consumption (10,000 kWh); repeated within each district–year |
| `energy_share_16district`, `elec_share_16district` | District shares of energy and electricity consumption, calculated over all 16 districts |
| `building_density` | Building footprint area divided by subdistrict area |
| `street_road_density` | Length of complete OSM road segments intersecting the subdistrict divided by projected area, km/km²; cross-boundary segments contribute to each intersected subdistrict |
| `poi_density` | Number of POIs divided by subdistrict area, points/km² |
| `green_ratio`, `industrial_ratio`, `commercial_ratio`, `residential_ratio` | Land-use area ratios calculated separately; their sum is not constrained to one |
| `log_ntl`, `log_poi_density`, `log_road_density` | `ln(1+x)` of the corresponding input |
| `log_building_density` | `ln(1+1000*building_density)` |

Citywide totals occur once per year and district totals once per district–year. Their repeated values in the subdistrict panel must not be summed over subdistricts. We hold the seven structural variables constant across 2016–2022, using the 2022 POI snapshot and the OSM snapshot dated 13 February 2026. Annual shortlist comparisons therefore use the same structural inputs in each year.

| Comparison file | Fields and coverage |
|---|---|
| `比较输入/edgar.csv` | `year, street_id, edgar_co2_ton`; EDGAR v8.0 all-sector emissions for 2016–2022, tonnes CO₂ |
| `比较输入/odiac.csv` | `street_id, odiac_annual_tCO2`; ODIAC2023 all-sector emissions for 2022, tonnes CO₂ |
| `比较输入/sectors.csv` | `year, city_scope1_mt, power_heat_scope1_mt`; 2016–2022 totals in million tonnes CO₂, whereas `panel.csv` uses 10,000 tonnes CO₂ |

We use EDGAR and ODIAC as all-sector spatial templates for the reallocation scenarios. They do not provide observed locations of electricity-and-heat facilities. Full reallocation holds the citywide total fixed and allows district shares to change. The upper-bound calculation also fixes each district total. The reallocatable proportion is measured against the citywide electricity-and-heat emission total.

## Frequency and scenario inputs

For the study shortlist, the frequency CSV contains `scope`, `year`, `model`, `street_id`, `baseline_rank`, `denominator`, `top35_count`, and `top35_frequency`. The reported scope is `continued_all`, the model is `M4`, and the year is 2022. Selection frequency is `top35_count / denominator`, with 1,000 as the reported denominator.

The scenario CSV contains `year`, `street_id`, `street_name`, `district_name`, `template`, `scenario_share`, `baseline_share`, and `scenario_rank`. It supplies the two full electricity-and-heat reallocation scenarios used with M4′ to define core-candidate membership. The script calculates M4′ from the panel and supplied model parameters.

## Additional inputs and data sources

The optional CBRA comparison needs `cbra.csv` with `year`, `street_id`, and `roof_density` for 2016–2021; the 2022 comparison uses the 2021 layer. We replace the building input while retaining the fitted coefficients and standardization parameters. This operation is not a new model fit.

The figure entry-point instructions list their additional map and plotting inputs. Retain all Shapefile companion files supplied with the boundaries. Raw rasters, point-level POIs, boundaries, saved figure inputs, and GIS preprocessing files are outside this distribution.

Source products: [CEADs](https://www.ceads.net/), [Beijing statistical yearbooks](https://nj.tjj.beijing.gov.cn/nj/qxnj/2022/zk/e/zk/indexch.htm), [EOG monthly VIIRS composites](https://eogdata.mines.edu/products/vnl/), [OSM/Geofabrik](https://download.geofabrik.de/asia/china.html), [EDGAR](https://edgar.jrc.ec.europa.eu/), [ODIAC](https://doi.org/10.17595/20170411.001), and [POI86](https://www.poi86.com/poi/amap/province/110000.html). The separately supplied `district_electricity_sources.csv` records the district yearbook source for each observation. Use those recorded source URLs for the district electricity data. Source products remain subject to their providers' terms.
